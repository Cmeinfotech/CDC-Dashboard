# Amazon product monitoring

CDC Amazon monitoring is scheduled on the Windows host every 30 minutes. The host must be awake and the scheduled task must be enabled; this is not an always-on hosted scheduler. Each scheduled run refreshes catalog/listing details, FBA inventory, Account Health, recent orders, and the dashboard database. Changes are detected on the next successful Amazon pull, then open dashboard pages refresh automatically. Amazon report processing can add delay, so this is periodic monitoring rather than real-time push.

The Windows task runs at normal priority (Task Scheduler priority 4) and launches Node directly. The machine must stay awake and the current Windows account must remain logged in. Catalog, FBA inventory, Account Health and recent orders run concurrently, with up to 22 minutes for pulls in the default 30-minute schedule. At least 2 minutes are reserved for database publication; if pulls finish earlier, publication can use the remaining cycle time. The Windows task has a 29-minute overall limit, leaving room for the next 30-minute trigger. Safe GET timeouts retry within each job; failed jobs preserve saved data and are reported as partial results. Status writes flush to disk before replacement and retain authenticated last-good backups. The status API reads catalog timestamps independently of automation metadata, so an unreadable status file cannot hide a committed pull as "Pending". Retention cleanup reads expiry headers instead of loading the complete snapshot history.

Run `npm run amazon:sync` to pull a fresh all-listings report and all available Catalog Items datasets. The dashboard action uses the same worker. Sync locks prevent overlapping runs. Failed or incomplete pulls preserve the previous committed comparison baseline. On Windows, install or update the 30-minute task with `powershell -ExecutionPolicy Bypass -File scripts/install-amazon-auto-sync-task.ps1 -IntervalMinutes 30`.

Keep `data-store/amazon-monitor` on persistent storage and back it up. It contains immutable source observations, comparisons, review acknowledgements, and sync history. Configure `AMAZON_MONITOR_DATA_DIR` to move it to another persistent directory. Never publish credentials or this data directory as public assets.

For deployment, provision a Node.js scheduler that runs `npm run amazon:sync` every 30 minutes from the application root with the same environment and persistent directory. The browser alone does not schedule pulls. Use only one scheduler for the application. FBA inventory and historical orders have separate source files; FBA inventory is refreshed each run, while recent order updates are merged into the separate order-history source.

Changes show detection time, previous/current values and API availability. They do not prove who changed a listing or when Amazon changed it. Ratings/review redistribution is not supplied by the configured product APIs. One unavailable catalog item remains explicitly flagged.

### Main administrator and reversing a parent merge

When a user confirms an ASIN history link or parent merge, the confirmation requires a reason (up to 1,000 characters). The encrypted review audit records that reason with the authenticated actor, exact confirmation time, and before/after identifiers. The reason appears in Preserved ASIN History and in the dedicated ASIN history page; exports include it as well.

Run `npm run admin:setup` in an interactive terminal. Select an enabled existing dashboard user ID (the configured loopback development user is also supported locally). Enter and confirm an administrator password of at least 12 characters; input is hidden. Restart the dashboard server after setup. The server stores only a salted scrypt hash in the ignored `.env` file, using `AUTH_MAIN_ADMIN_USER_ID` and `AUTH_MAIN_ADMIN_PASSWORD_HASH`. The configured main administrator receives access to both dashboard accounts. Do not share the password in chat or commit `.env`.

In a merged child's review, the main administrator can choose **Reverse merge**, review B → A, and enter their password. Other users cannot call this endpoint successfully, even with a correct password. Five failed attempts lock password verification for 15 minutes. The operation atomically updates only the selected SKU's local parent mapping and appends the authenticated actor, time, and previous/current parents to encrypted audit history. Legacy merges retain a legacy actor label when their original actor was not recorded. Audit history is visible in the review and dedicated ASIN history page. Retention follows the existing encrypted Amazon storage policy.

A reversal does not call Amazon or change source snapshots or sales totals. Repeating a reversal or reversing a superseded mapping is rejected. Future completed Amazon pulls remain authoritative, as with forward merges. Reversal restores a previous local parent assignment; it is not an Amazon listing edit.
